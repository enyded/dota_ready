ReAccept connects one Android device to one Windows PC so the user can receive a Dota 2 ready-check notification and request acceptance remotely.

Data processed

The service processes randomly generated installation identifiers, device and PC public keys, the PC name supplied by Windows, pairing status, online/Armed status, match-event identifiers and timestamps, requested actions, and execution results. The production backend runs on a KVM VPS from QDE (qde.com), with Cloudflare in front as a reverse proxy for DNS, TLS termination, and DDoS protection. The origin server's own request/access logging is intentionally disabled; Cloudflare, as the edge proxy, may still process and log ordinary connection metadata (IP address, request timestamps) per its own logging and retention practices.

Ready-check (match-found) detection is entirely local: the Windows Agent never uploads a screenshot or any captured pixels for that flow. Party-invite detection is different: to show who is inviting you, the agent crops a small, bounded region of the party-invite dialog (never the full desktop) — this can include the inviting player's Steam display name and avatar image — encodes it as WebP (roughly 420×110px, capped at 100 KB), and uploads it to the backend so it can be relayed to your phone and, if you've linked Telegram, sent as a Telegram photo. This preview is stored in the backend database (to support resending it if your phone reconnects) and is hard-deleted along with its party-invite event after the same 40-day retention window described below; it is excluded from the internal admin/support panel and is never written to application logs or metrics. Capture is best-effort — if it fails, a plain-text notification is sent instead. The Android app does not request direct camera permission and does not store QR images; it receives only the scanned one-time pairing value from the system scanner. The current app contains no advertising SDK or product analytics SDK.

Purpose and sharing

Data is used only to authenticate paired installations, relay connection state and match events, prevent replay, diagnose service operation, and deliver the requested result. It is not sold. It is disclosed only to infrastructure providers required to operate the service or when legally required. Production processors: QDE (VPS hosting), Cloudflare (reverse proxy, DNS, and DDoS protection), Google Firebase (Firebase Authentication, for device identity), and Telegram (Telegram Bot API, only for users who choose to link a Telegram companion; this can include forwarding a party-invite preview image as described under "Data processed" above).

Storage and security

Android private keys are generated in Android Keystore and are not sent to the backend. The Windows Agent pins the backend command-signing public key. Pairing codes are random, one-time, expire after three minutes, and are stored by the backend as hashes. Production clients require encrypted HTTPS/WSS transport.

The current backend records installations, revoked pairing records, match events, and commands in its database. Match events, party invites, and their associated commands are automatically hard-deleted after 40 days (configurable). Device/PC installation records and revoked pairing records have no automatic deletion schedule and are retained until removed on request (see "User choices and deletion" below). Local Android history and pairing settings remain on the device until app data is cleared or the app is uninstalled.

User choices and deletion

The user can Disarm event delivery or Unpair the phone and PC in Settings. Unpairing revokes access but does not currently erase historical backend records. To request access or deletion, contact support@re-accept.com. Document and operationally verify that request process before public release.

Children and changes

The service is not directed to children. Material policy changes will be published at the same stable URL with a new effective date. Questions may be sent to support@re-accept.com.
